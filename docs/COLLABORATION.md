## 文件与代码

- `data/original/`、`legacy/`、`results/legacy/` 保持快照；新工作放 `scripts/`、个人 notebook 或 `results/<方法>/<日期>/`。
- 每次实验记录输入 hash、标签正类、日期划分、特征名单、预处理拟合期、随机种子、软件版本、运行命令和输出位置。复制旧结果时必须带版本说明。
- 本 project 作为独立 Git 仓库连接 `git@github.com:Sundance0604/ECO6109.git`，不改上层课程仓库的远程设置。分支建议 `codex/<topic>` 或成员自选规范；一次改一件事，由另一位组员复核。
- Excel 二进制文件不同时编辑；新数据另存版本，不反复覆盖。代码用相对路径，避免 `os.chdir` 到个人机器路径和导入时自动连 Wind。
- 旧 notebook 有多个覆盖 `df_clean` 的清洗版本，不可依靠执行顺序猜数据状态。新模型使用明确入口，或按模型分开 notebook。

## 怎样判断结果值得写入报告

先确认所有模型在同一组测试日期、同一标签定义下比较。Accuracy、F1、Precision、Recall、AUC 之外，列出测试样本数与正类比例；同时给多数类和方向延续基准。高 F1 可能来自持续预测多数类。

阈值、特征筛选和超参数只看训练/验证集。由于历史材料已经反复查看测试期，本项目无法把该时期重新宣称为从未接触过的样本；应披露这一点，并考虑固定 rolling-origin 方案或有真实新数据时增加后续检验。新脚本中的固定测试区间便于统一复核，不会消除历史研究选择偏差。

结果表由数据生成，统一保留 3–4 位有效小数，图标明样本、单位、正类和来源。不要把旧截图放正文。若只研究方向分类，不必强行加入回测收益；如果加入，需能独立解释价格近似、久期、票息、成本与信号时点。

## 独立检查

让未写模型代码的组员用 Excel 或独立程序，从 `results/baseline/test_predictions.csv` 逐行统计预测是否正确，再除以样本数；并从原始收益率抽查标签、边界日期、持平情况。`scripts/verify_results.py` 提供独立的标准库实现，与模型指标函数无依赖关系。小组还需亲自执行、记录检查人和结论，不能把 AI 的复述当作人类复核。

目前不填写虚假的成员、学号、复核人、已完成任务或最终研究结论。
